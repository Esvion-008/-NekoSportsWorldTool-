# 运动世界校园 路线生成 V2 企划书

> 版本：v1.0（定稿候选）　　日期：2026-10-24　　状态：待"开始阶段 1"指令
> 原则：本企划书定稿前不改动任何源代码；每阶段交付后先验收，再进下一阶段。

---

## 1. 背景与目标

现有路线生成方式是「打卡点拟合闭合环 + 随机起点相位 + 平滑速度曲线」，存在两个真实感缺陷：

1. 环线不贴合校园真实路网，会穿楼、穿草坪，人工复核对图一眼可见；
2. 环线形状每天趋同，跨天自相似度高。

V2 目标：**在校园真实路网与禁行区约束下，生成一条长度精确、经过全部打卡点、终点落在真实 POI 的可解释跑步路线**，并保留现有全部协议层（提交格式、10 秒窗校验、哨兵点、步频、海拔）。

**成功标准**

| 指标 | 目标值 |
|---|---|
| 路线越界（进禁行区/出允许区域） | 0 次 |
| 长度精度 | 2000 ± 5 m（例外区间见 §4） |
| 打卡点覆盖 | 100%（≤3 m 内经过） |
| 生成耗时 | 单账号 ≤ 2 s |
| 首次实跑判定 | 有效 |

## 2. 范围

**做**

- 校园区域 / 禁行区 / 走廊 / POI 的 GeoJSON 导入、校验、持久化与版本快照
- 真实路网导入、裁剪、建图、A* 寻路、点阵补充
- 候选路线有界枚举（Top 10–20）、评分与去重
- 椭圆弧倒角 + 横向抖动 + 直曲比例控制的几何造型
- 距离补足：随机终点、绕行段、折返、超长回落
- 矢量预览画布 + 缩略图列表 + 单条重生成 + 整批确认
- 两天一批的批量执行与逐账号日志
- 单账号实跑验证后才放开批量

**不做**

- 不内置在线瓦片地图（用外部 QGIS/GeoJSON 工具绘制后导入）
- 不引入 WebView / Leaflet / MapLibre
- 不做暂停 / 休息段功能（已作废）
- 不做多校区支持（单校区，预留数据结构）
- 不用贝塞尔自由曲线、抛物线、双曲线（只保留椭圆弧）
- 不用 RSA 做随机源（用现有 seeded PRNG）
- 不改动现有提交流程（`submit.rs` 的字段与语义保持）

## 3. 术语与不变量

| 术语 | 定义 |
|---|---|
| 打卡点 | 服务端点位接口返回的 BD 坐标点，每次运行前实时拉取 |
| 末打卡点 | 生成顺序中的最后一个打卡点（"最终终点/打卡终点"） |
| 终点 | 记录结束位置，从 POI（食堂/宿舍/校门）中选一个 |
| 巡回路 | 从第一个打卡点起，依次经过全部打卡点、绕开禁行区的路段 |
| 绕行段 | 补齐距离用的环路，80–300 m，最多 2 段 |
| 折返 | 到另一个 POI 再原路返回原 POI，计入总距离，最多 1 次/2 km |
| 净空 | 路线距禁行区边界的最小距离：1.5 m（窄走廊 0.8 m） |
| 允许区域 | 校园多边形内缩 10 m |

**不变量（每条候选路线必须同时满足）**

1. 起点 = 第一个打卡点
2. 巡回路踩完全部打卡点；顺序 = 首个固定 + 其余重排
3. 巡回路 ≤ 2000 m
4. 总距离 = 2000 ± 5 m（例外见 §4.3）
5. 全程在允许区域内，不进禁行区，净空达标
6. 打卡点/POI 落在禁行区时：以点位为准开 3 m 可行走小圆
7. 无暂停、无休息段，提交体 pause 恒为 0
8. 只使用椭圆弧倒角，切线连续；无贝塞尔/抛物线/双曲线
9. 转向角 45–90° 允许，弧半径 1.5–3 m；直线段最短 20 m
10. 直线段占比 40–60%，曲线段占比 40–60%（互斥，合计 100%）
11. 折返处为 3–6 m 直径弧形过渡 + 横向抖动，禁止尖点
12. 距离由路线长度决定，不再先抽 2–2.5 km

## 4. 距离规则（核心数值）

### 4.1 正常情况

- 巡回路长度 `L_tour`
- 剩余量 `R = 2000 − L_tour`
- 从末打卡点沿路网选终点 POI，使 `巡回路 + 末段 = 2000 ± 5 m`
- 优先选距离最接近 R 的 POI（先按剩余距离过滤，再在合格集合内随机）

### 4.2 余量不足或过多

| 情形 | 处理 |
|---|---|
| 到最近 POI 也超出 R | 缩短末段：换更近的 POI；仍不行则本候选作废 |
| 末段远小于 R（余量过多） | 插入绕行段（80–300 m，≤2 段） |
| 绕行后仍不足 | 折返（去另一个 POI 再回到原 POI；2×距离），≤1 次/2 km |
| 折返后仍不足 | 换下一个候选（顺序/路径组合），Top 候选耗尽则本账号跳过并报告 |

### 4.3 巡回路超长回落

| 情形 | 处理 |
|---|---|
| `L_tour ≤ 2000` | 按 §4.1 补到 2000 ± 5 |
| `2000 < L_tour ≤ 2050` | 跑完全部打卡点即止，不加尾段 |
| `L_tour > 2050` | 跑完后追加 30 ± 5 s（约 75–100 m），结束于允许区域内任意可行走点，不要求 POI |
| 总长 > 2150 | 换顺序重试（≤5 次）；仍超则跳过该账号并在批次报告标红 |

### 4.4 精度实现

距离容差 ±5 m 由三处吸收：末段 POI 距离取整、绕行段长度微调（±30 m 内）、最后 5% 路程的抖动幅度微调。

## 5. 数据契约

### 5.1 输入 1：`campus.geojson`（WGS84）

| 要素 | 属性 | 说明 |
|---|---|---|
| Polygon | `kind = "area"` | 校园允许区域外边界 |
| Polygon | `kind = "blocked"` | 禁行区（建筑 / 水面 / 施工） |
| Polygon | `kind = "corridor"` | 可选：路网缺失处的可行走走廊 |
| Point | `kind = "poi_canteen"` | 食堂（每类 2–4 个） |
| Point | `kind = "poi_dorm"` | 宿舍 |
| Point | `kind = "poi_gate"` | 校门 |

坐标顺序 `[lng, lat]`；导入后统一转换 `WGS84 → GCJ02 → BD09`（误差 1–2 m）。

### 5.2 输入 2：`roads.geojson`（WGS84）

`LineString` 集合（footway / path / cycleway / residential / service / living_street），导入后裁剪到允许区域内。

### 5.3 持久化：`campus.json`（BD 坐标）

内容：允许区域、禁行区、走廊、POI、路网、净空参数、基准海拔（默认 82 m）、版本号与修改时间。
每次修改生成一个版本快照，历史轨迹可复现。

### 5.4 坐标处理

- 内部统一使用 BD09；
- 几何计算投影到本地米制平面（以校区质心为原点、等距圆柱投影、经度按纬度余弦缩放）；
- 提交给服务端时沿用现有 BD→GCJ02 转换（`src/track/wire.rs`）；
- 勾选"基准海拔"后，海拔曲线以此为中心均值回归。

## 6. 算法设计

### 6.1 路网与寻路

1. 路网裁剪到允许区域 → 去除落在禁行区内（含净空膨胀）的边
2. 建无向图：节点 = 路网顶点 + 投影点；边权 = 米制长度
3. A* 启发式 = 直线距离；转角代价按角度加权（抑制连续 90° 折线）
4. 打卡点 / POI / 绕行锚点投影到最近边接入
5. 5 m 点阵：仅在"距路网 > 15 m 的开阔区"生成，作为可选控制点（不强制经过），用于广场/操场的平滑曲线

### 6.2 打卡点顺序

- 首个打卡点固定
- N ≤ 6：全排列（≤120 种）
- N > 6：贪心最近邻 + 2-opt 改进
- 每段用 K 最短路（K = 2–3）提供备选
- 组合搜索用 beam search 控制规模（每层保留前 30–50 个部分路径），最终输出 Top 10–20

### 6.3 几何造型

1. 折线 → 转角识别（>15° 视为转角）
2. 转角按 45–90° 用 1.5–3 m 半径椭圆弧倒角（两端切线连续）；小转角用 2–5 m 圆弧
3. 直线段与曲线段占比检查（曲率半径 < 50 m 计为曲线），不满足 40–60% 则调整候选
4. 横向 AR(1) 抖动：σ = 0.3–0.8 m，按 5–10 m 采样叠加
5. 折返处：3–6 m 直径 U 型弧 + 抖动
6. 速度-曲率耦合：转角处按 `v ≤ √(a·r)`（a ≈ 1.5–2.5 m/s²）降速 10–20%，但不得低于 1.9 m/s（有效窗口下限）

### 6.4 候选评分与去重

- 评分：`|L − 2000|` 越小越好 → 转角数越少越好 → 最低净空越大越好 → 直曲比例偏差越小越好
- 去重：两条候选采样点相似度 > 90% 视为重复，只保留评分更高的一条
- 输出：Top 10–20（默认 12）

## 7. 业务流程

```
一次准备：GeoJSON 导入 → 校验 → 存 campus.json（改动才重做）
    ↓
每批（2 天）：
  1. 拉取实时打卡点（所有账号共用同一次点位请求，遵守 5 分钟限 3 次）
  2. 每账号独立生成 Top 10–20 候选 → 自动选 1 条
  3. 预览画布/缩略图 → 可单条重生成/换候选 → 整批确认一次
  4. 两天内按 7:00–20:00 随机窗口执行，每账号每天 1 次，两次间隔 ≥12 h
  5. 每次完成刷新达标与公里；失败进入失败名单，可重试
```

**确认交互**：每账号一行（总长 / 巡回路 / 终点 / 转角数）+ 缩略图；支持单条重生成、换候选、导出 PNG；批量确认一次；执行期可暂停/取消/查看进度。

**日志**：沿用现有逐账号前缀日志（登录、刷跑、路线生成、距离校验全部带账号标记）。

## 8. 协议层改动边界

**保持不变**

- 提交字段与语义（`startTime/stopTime/totalTime/totalDis/validDis/validTime/speedPerTenSec/...`）
- 10 秒窗配速校验（141–600 秒/公里）
- 点位哨兵（type=5 / type=6 / 首点 type∈{0,7}）
- 结尾断崖、点类型散布、首点速度修正
- 步频/步幅/海拔后处理
- OBS 两段上传 + 详情验证
- 批量并发、失败名单、备份

**改变**

- 几何来源：拟合环 → 路网 + 禁行区 + 椭圆弧 + 抖动
- 距离来源：随机区间 → 路线长度（2000 ± 5 m）
- 开始时刻约束：时长由路线长度与配速决定，仍满足"开始时刻 + 时长 ≤ 当前时刻"

**开关**：新增 `route_engine = v1 | v2`，默认 v1；单账号实跑验证通过后才切 v2，可随时回滚。

## 10. 测试与验收

**几何断言**

- 路线不进禁行区，且边界最小距离 ≥ 净空
- 每个打卡点 3 m 内经过
- 总长 2000 ± 5 m（或落在 §4.3 例外区间）
- 直线占比 40–60%
- 曲率有界（无尖点）；折返 ≤1 次/2 km

**协议断言**

- 所有 10 秒窗配速落在 141–600 秒/公里
- `totalDis` = 路线长度（取整一致）
- `totalTime` = 距离 ÷ 配速（含现有修正）
- 步频 100–200 步/分；爬升与基准海拔一致
- 哨兵/断崖/首点规则保持

**实跑验收**

1. 单账号提交 1 次 → 拉详情确认有效
2. 通过后再放开批量；不通过则回退 v1 并定位差异
