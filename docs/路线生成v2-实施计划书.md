## 2. 目标与硬性不变量

**目标**：在校园真实路网与禁行区约束下，生成长度精确（2000±5m）、经过全部打卡点、终点落在真实 POI 的跑步路线，并保留现有全部协议层。

**12 条不变量（每条候选路线必须同时满足）**

1. 起点 = 第一个打卡点（服务端点位顺序的第一个）
2. 巡回路踩完全部打卡点；顺序 = 首个固定 + 其余重排
3. 巡回路 ≤ 2000 m
4. 总距离 = 2000 ± 5 m（例外见 §6.3）
5. 全程在允许区域内、不进禁行区、净空达标
6. 打卡点/POI 落在禁行区时：以点位为准开 3 m 可行走小圆
7. 无暂停、无休息段；提交体 pause 恒为 0
8. 只用椭圆弧倒角（切线连续）；禁止贝塞尔/抛物线/双曲线
9. 转向角 45–90° 允许，弧半径 1.5–3 m；直线段最短 20 m
10. 直线段 40–60%、曲线段 40–60%（互斥，合计 100%）
11. 折返处为 3–6 m 直径弧形过渡 + 横向抖动，禁止尖点
12. 距离由路线长度决定，不再先抽随机距离

**术语**

| 术语 | 含义 |
|---|---|
| 打卡点 | 点位接口返回的 BD 坐标点 |
| 末打卡点 | 生成顺序中的最后一个打卡点 |
| 终点 | 记录结束位置，从 POI（食堂/宿舍/校门）中选 |
| 巡回路 | 从第一个打卡点起经过全部打卡点、绕开禁行区的路段 |
| 绕行段 | 补齐距离用的环路，80–300 m，≤2 段 |
| 折返 | 到另一个 POI 再原路返回原 POI，≤1 次/2 km |
| 净空 | 距禁行区边界的最小距离：1.5 m（窄走廊 0.8 m） |
| 允许区域 | 校园多边形内缩 10 m |

## 4. 数据契约

### 4.1 输入 1：`campus.geojson`（WGS84，外部工具绘制）

| 要素 | properties | 说明 |
|---|---|---|
| Polygon | `kind="area"` | 校园允许区域外边界（1 个） |
| Polygon | `kind="blocked"` | 禁行区（建筑/水面/施工，多个） |
| Polygon | `kind="corridor"` | 可选：路网缺失处的可行走走廊 |
| Point | `kind="poi_canteen"` | 食堂，每类 2–4 个 |
| Point | `kind="poi_dorm"` | 宿舍 |
| Point | `kind="poi_gate"` | 校门 |

坐标顺序 `[lng, lat]`。导入后 `WGS84 → GCJ02 → BD09`（误差 1–2 m，可接受）。

### 4.2 输入 2：`roads.geojson`（WGS84，Overpass Turbo 导出）

`LineString` 集合：footway/path/cycleway/residential/service/living_street。导入后裁剪到允许区域。

### 4.3 持久化：`campus.json`（BD 坐标）

字段：`version`、`created_ms`、`area`、`blocked[]`、`corridors[]`、`pois{canteen[],dorm[],gate[]}`、`roads`、`clearance_min/max`、`base_altitude_m`（默认 82）、`allow_shrink_m`（10）。
每次保存生成版本快照（保留最近 N 版），旧轨迹可复现。

### 4.4 坐标与投影

- 内部统一 BD09
- 几何计算投影到本地米制平面：以校区质心为原点，等距圆柱，经度乘 `cos(lat)`
- 提交时沿用现有 `wire.rs` 的 BD→GCJ
- 海拔以 `base_altitude_m` 为中心均值回归

## 5. 算法要求

### 5.1 路网建图

- 裁剪：路网 ∩ 允许区域，剔除落入禁行区（含净空膨胀）的边
- 节点 = 路网顶点 + 投影点；边权 = 米制长度
- A*：启发式 = 直线距离；转角代价按角度加权（抑制连续 90° 折线）
- 打卡点/POI/锚点投影到最近边接入
- 5 m 点阵：仅在距路网 > 15 m 的开阔区生成，作为可选控制点（不强制经过）

### 5.2 打卡点顺序

- 首个固定
- N ≤ 6 全排列（≤120 种）；N > 6 贪心最近邻 + 2-opt
- 每段 K 最短路（K = 2–3）
- Beam search 控制组合规模（每层保留前 30–50 部分路径），最终 Top 10–20

### 5.3 几何造型

1. 折线 → 转角识别（>15° 为转角）
2. 45–90° 转角：1.5–3 m 半径椭圆弧倒角，切线连续；小转角用 2–5 m 圆弧
3. 直/曲占比（曲率半径 <50 m 计为曲线）必须落 40–60%
4. 横向 AR(1) 抖动：σ=0.3–0.8 m，按 5–10 m 采样
5. 折返：3–6 m 直径 U 型弧 + 抖动
6. 速度-曲率耦合：转角处 `v ≤ √(a·r)`（a≈1.5–2.5 m/s²）降速 10–20%，不低于 1.9 m/s

### 5.4 评分与去重

- 评分顺序：`|L−2000|` 小 → 转角数少 → 最低净空大 → 直曲比例偏差小
- 去重：采样点相似度 >90% 视为重复，保留评分高者
- 默认输出 12 条（10–20 可配）

## 6. 距离规则

### 6.1 正常

- 巡回路长度 `L_tour`；剩余 `R = 2000 − L_tour`
- 从末打卡点沿路网选终点 POI，使总长 2000±5 m
- 先按剩余距离过滤 POI，再在合格集合内随机

### 6.2 余量调整

| 情形 | 处理 |
|---|---|
| 最近 POI 也超出 R | 换更近 POI；不行则本候选作废 |
| 末段远小于 R | 插入绕行段（80–300 m，≤2 段） |
| 仍不足 | 折返（去另一个 POI 再回来），≤1 次/2 km |
| 仍不足 | 换候选；Top 候选耗尽 → 本账号跳过并报告 |

### 6.3 巡回路超长回落

| 情形 | 处理 |
|---|---|
| `L_tour ≤ 2000` | 补到 2000±5 |
| `2000 < L_tour ≤ 2050` | 跑完即止，不加尾段 |
| `L_tour > 2050` | 加 30±5 s（约 75–100 m）尾段，结束于允许区域内任意可行走点，不要求 POI |
| 总长 > 2150 | 换顺序重试（≤5 次）；仍超则跳过该账号并标红 |

### 6.4 容差吸收

±5 m 由三处吸收：POI 距离取整、绕行段长度微调（±30 m）、最后 5% 路程抖动幅度微调。

## 7. 阶段任务（按顺序交付，逐个验收）

### 阶段 1｜地图数据导入与校验（2–3 天）

- 新建模块：`src/campus/mod.rs`（数据结构）、`src/campus/import.rs`（GeoJSON 解析 + 坐标转换 + 校验）、`src/campus/store.rs`（campus.json 读写 + 版本快照）
- 新增 UI：`src/ui/campus.rs`（导入按钮、统计信息、矢量画布、错误列表）
- 校验项：多边形闭合、自交、面积下限、blocked 必须落在 area 内、POI 必须在允许区域且不在 blocked 内、坐标范围合法
- **验收**：能导入、能列出区域/禁行/POI 数量、画布正确显示、错误明确、重启不丢

### 阶段 2｜POI 与人工确认（1 天）

- POI 展示/编辑/删除；点击画布取坐标；合规校验（在允许区域内、不在禁行区）
- **验收**：点击取坐标正确；不合规 POI 被拒并说明原因

### 阶段 3｜路网与寻路内核（3 天）

- `src/campus/graph.rs`：建图（净空膨胀、裁剪）、A*、投影接入
- 点阵生成（开阔区）
- 单元测试：任意两点可寻路、路径不进禁行区、单次 <100 ms
- **验收**：见测试；用示例数据输出路径并可视化

### 阶段 4｜候选路线生成（5 天）

- `src/route/mod.rs`：顺序枚举、K 最短路、beam search、距离规则、评分去重
- `src/route/shape.rs`：椭圆弧倒角、抖动、直曲比例、速度-曲率耦合
- 对接现有速度/步频/海拔后处理（复用 `postfix.rs` 与 `generator.rs` 的曲线部分）
- **验收**：单账号 ≤2 s；12 条不变量全部满足；输出 Top 10–20

### 阶段 5｜预览与确认（2 天）

- 画布叠加：区域/禁行/路网/打卡点/POI/候选路线
- 缩略图列表：总长/巡回路/终点/转角数；单条重生成/换候选；导出 PNG
- **验收**：一眼看出越界/漏点/长度异常；确认后进入执行队列

### 阶段 6｜批量执行（两天一批，2 天）

- 接入 `ui/accounts.rs` 批量框架：每账号独立路线、两天各一次、窗口 7:00–20:00 随机、间隔 ≥12 h
- 进度/暂停/取消/失败重试；日志带账号前缀
- **约束**：本阶段之前不改提交流程
- **验收**：批量两天执行成功；失败可重试；日志完整

### 阶段 7｜单账号实跑验证（1 天）

- 单账号提交 1 次 → 拉详情确认有效
- 通过后切 `route_engine=v2`；否则回退 v1 并定位

## 8. 测试与验收断言

**几何**

- 不进禁行区，边界最小距离 ≥ 净空
- 每个打卡点 3 m 内经过
- 总长 2000±5（或 §6.3 例外）
- 直线占比 40–60%
- 曲率有界、无尖点；折返 ≤1 次/2 km

**协议**

- 所有 10 秒窗配速在 141–600 秒/公里
- `totalDis` = 路线长度（取整一致）
- `totalTime` = 距离 ÷ 配速（含现有修正）
- 步频 100–200 步/分；爬升与基准海拔一致
- 哨兵/断崖/首点规则保持

**实跑**

1. 单账号 1 次 → 详情有效
2. 通过后再批量；不通过回退 v1

## 9. 风险与回滚

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 服务端校验打卡点顺序 | 首个固定；保留顺序模式开关 |
| R2 | 服务端校区多边形不一致 | 允许区域内缩 10 m；净空 1.5 m |
| R3 | 折返/掉头被判异常 | ≤1 次/2 km，弧过渡 + 抖动 |
| R4 | OSM 路网缺失 | 走廊补充 + 点阵选点 |
| R5 | 跨账号路线相似 | 每账号独立枚举 + 随机终点 + 抖动 |
| R6 | 距离口径影响已购账 | 按 2 km/次记账（已确认） |
| R7 | 巡回路必然超长 | §6.3 回落规则 |
| R8 | 容差吸收失败 | 微调绕行/末段抖动，候选重试 |

**回滚**：`route_engine = v1 | v2`，默认 v1；`campus.json` 版本快照独立，互不污染。
